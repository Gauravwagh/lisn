# AGENTS.md — how lisn is built

Read this before changing anything. It explains the architecture, the invariants that
keep highlighting in sync with the voice, and how the pieces fit. All 8 roadmap phases
are implemented; the "Known gaps" section lists what is still rough.

## Purpose

A local, free TTS reader. The user listens *and* watches: the current sentence is
highlighted and the current word is bold. Word-level sync is a core feature, which is
why engine choice and the text pipeline are shaped around **word timings**.

## Data flow

```
source ─extract─▶ Blocks ─normalize+segment+expand─▶ Document(sentences)
                                                           │
   Player ──goto/play/pause──▶ Prefetcher(engine, cache) ──┘  synthesizes speech_text
     │                              │
     │◀── Audio(samples, timings mapped to display words)
     ▼
   Output (PortAudio callback) ── position() ──▶ word_index ──▶ PlayerEvent("word")
                                                     │
            TUI (call_from_thread) · headless (rich Live) · server (SSE) · MCP (status)
```

## Invariants (do not break)

1. **Display text vs speech text.** `Sentence.text` is shown; `Sentence.speech_text` is
   spoken. `Sentence.word_map[i] = (start, end)` is the span of speech words that display
   word `i` expanded into. `expand_text` works token-by-token precisely so this map exists.
   Any new expansion rule must keep one display token -> contiguous speech words.
2. **Engines report timings per speech word** (whitespace-split). `timing.display_word_timings`
   maps them back; if the count does not match, it falls back to a proportional spread
   rather than crashing. Engines without timings return `timings=()`.
3. **Immutability.** Document, Sentence, Config, PlayerState, Audio are frozen dataclasses.
   The Player replaces its state (`dataclasses.replace`) instead of mutating it. Mutable
   state exists only inside `audio.py` buffers and the prefetcher's future map, behind locks.
4. **Never call an engine concurrently.** The Prefetcher has exactly one worker; engines
   also hold their own lock.
5. **Cache key = (engine, voice, speed, speech_text).** Changing any of them invalidates.
6. **Stable ids.** `sentence_id(text, occurrence)` hashes the text plus its repeat count,
   so edits elsewhere in a document do not shift ids. Resume stores id + index and prefers id.
7. **Errors are LisnError subclasses** with user-safe messages; the CLI prints them and
   exits 1, the API returns 400.
8. **The server binds to 127.0.0.1 only** and every route except /health needs the token
   (Authorization: Bearer, or ?token= for EventSource).

## Player state machine

Statuses: IDLE → LOADING (future pending) → PLAYING → … → FINISHED, with PAUSED, STOPPED,
ERROR. Commands are queued and drained on the player thread every 20 ms; the tick polls
the pending future (non-blocking) or tracks the current word with `bisect` over word start
times. Pause during LOADING parks the audio at its first word. Speed/voice changes
re-synthesize the current sentence and resume at the current word's start time (scaled for
speed). A sleep timer is a monotonic deadline checked each tick. Listener callbacks run on
the player thread and must be quick; exceptions in listeners are swallowed.

## Extension notes

- Highlighting uses the CSS Highlight API (`CSS.highlights`, Chrome 105+), so the page DOM
  is never mutated. Sentences from the server are located in the page's text nodes by a
  whitespace/quote-insensitive search (`normalize()` in content.js); unmatched sentences
  simply get no highlight.
- Google Docs renders to canvas, so the content script sends the URL and the server uses
  the public export (or the Drive API when signed in). Selecting text and using
  "Read selection" also works there.
- Without `lisn serve`, the Web Speech API reads the text with `onboundary` word events.

## Conventions

- Python 3.11/3.12, type hints everywhere, `from __future__ import annotations`.
- Files stay small (<450 lines); one concern per module.
- Validate at boundaries (CLI args, config, API bodies, external text); fail fast with LisnError.
- Optional dependencies are imported lazily inside functions (see registry.py, extract/).
- Tests: unit tests for every pure module; the Player, TUI, server and MCP are tested with
  `FakeEngine` + `SilentOutput(time_scale=…)`; real-model tests are `@pytest.mark.slow`.
- Lint/format: `ruff check . && ruff format .` (line length 120).

## Known gaps / next ideas

- Cold start to first audio is ~4.5 s (torch + model load). Let `lisn read` reuse a running
  `lisn serve` instead of loading its own model.
- Piper has no word timings; proportional highlighting only.
- The extension has been syntax-checked and its server contract is tested, but it has not
  been exercised in a real browser session yet. Google Docs reading depends on export access.
- Export is sequential; a parallel renderer would speed up long books.
- Speed changes re-synthesize instead of time-stretching, so there is a short gap.
